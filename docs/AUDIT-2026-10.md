# Security Audit — Basalt 1.1.1 and DarwinFUSE (October 2026)

Scope: Basalt `138e187` (v1.1.1, including the embedded copy of DarwinFUSE in
`src/DarwinFUSE`) and the standalone DarwinFUSE repository `3026545`.

Method: manual source review of the crypto core, volume/header handling, RNG,
memory handling, FUSE service, the DarwinFUSE NFSv4 server, the ObjC++ bridge,
the SwiftUI app, the CLI and the build scripts. The platform-independent core
(`Crypto`, `Common`, `Volume`, `Platform`) and the DarwinFUSE server were compiled
on Linux and exercised:

- built-in self-tests (`EncryptionTest`, `PlatformTest`), software and hardware AES;
- Argon2id against libargon2 (argon2-cffi) and the official RFC 9106 §5.3 vector;
- header compatibility: volumes created by the unmodified 1.1.1 code opened,
  upgraded and reopened by the fixed code (PBKDF2 and Argon2id variants);
- sector I/O with wrapping offsets against old and new code;
- NFS server over a Unix socket: access from another UID, peer check, READ with
  out-of-range offsets, LOOKUP with traversal names (standalone DarwinFUSE);
- AES-NI vs. software AES on random keys/data.

Not covered by tests: Swift and ObjC++ code (no macOS toolchain), the macOS
kernel NFS client, `hdiutil`, and anything that needs a real mount. The checklist
at the end lists what has to be verified on a Mac before a release.

## Findings

### B-1 / D-1 — Unauthenticated loopback NFS server (Critical)

`nfs4_server_create()` bound `127.0.0.1:<ephemeral>`. Any local process can find
the port with a trivial scan and speak NFSv4 to it. The only access check,
`FuseService::CheckAccessRights()`, compares `fuse_get_context()->uid`, which
DarwinFUSE takes from the client-supplied AUTH_SYS credential. Consequences:

- every local user (and every sandboxed app with the network client entitlement)
  can read the *decrypted* volume image and write to it;
- TCC protections for removable/network volumes are bypassed;
- combined with B-3, a client can overwrite the volume headers.

Fix: the server listens on a Unix domain socket in a private `mkdtemp()`
directory (0700) and rejects peers whose UID is neither 0 nor the owner
(`LOCAL_PEERCRED`). `mount_nfs -o vers=4,proto=ticotsord,port=<socket>,nocallback "<socket>:/"`
is supported by `mount_nfs` (NFS-136 and later) and by the kernel NFS client
(xnu since 10.15, `nm_nfs_localport`). `nocallback` is required: with NFSv4
callbacks enabled, `nfs4_setclientid()` needs an IPv4/IPv6 address for the
callback channel and fails with EINVAL on a local socket (the first test on
macOS fell back to TCP without it). Verified on macOS; the TCP fallback is
off by default since then (`-DDFUSE_TCP_FALLBACK=1` re-enables it for
diagnosis), so a failed local mount is an error rather than silently insecure.

### B-2 — Argon2id deviates from RFC 9106 (High)

`fill_block()` in `src/Crypto/Argon2/core.c` had two defects:

1. `with_xor` was ignored, so passes after the first overwrite blocks instead of
   XOR-ing into them (Argon2 v1.0 behaviour, although v1.3 is hashed into H0);
2. in the row round the diagonal step passed the wrong words as the `d` input of
   G (v13/v14/v15/v12 instead of v15/v12/v13/v14), so the permutation lost its full
   diffusion.

The self-test vectors had been produced by the same code and therefore passed.
With both lines corrected the output matches libargon2 for all tested parameters
and the RFC 9106 §5.3 vector (`0d640df5…e659`).

Practical impact: the variant is still memory-hard and not known to be weak, but
it is unanalysed, lacks the v1.3 tradeoff mitigation, and volumes depend on
Basalt's own code to be opened. The fix keeps the old function verbatim as an
open-only KDF ("Argon2id (legacy)", "Argon2id-Max (legacy)"); the mount dialog and
CLI offer the existing header upgrade. Opening a not-yet-upgraded volume costs one
extra Argon2 run. Downgrade note: volumes created after this change cannot be
opened by Basalt ≤ 1.1.x — release it as 1.2.0.

### B-3 — Sector bounds overflow (High)

`Volume::WriteSectors()` checked `byteOffset + length > VolumeDataSize`. With
`byteOffset = 2^64 − 65536` (an NFS WRITE at offset `0xFFFF…0000`, i.e. a negative
`off_t`) the sum wraps to 0, the check passes, and the data is encrypted and
written 64 KiB *before* the data area — exactly the hidden volume header. Hidden
volume protection does not trigger because the target lies outside the protected
range. Demonstrated against the 1.1.1 code (hidden header area checksum changed).
`ReadSectors()` had no range check, and `fuse_service_read()` underflowed for
offsets beyond the end. All three are fixed; NFS READ/WRITE now also reject
offsets that do not fit `off_t`.

### B-4 — Log file in /tmp (Medium)

`DFUSE_LOG`/`DFUSE_ERR` appended to `/tmp/darwinfuse.log` in release builds,
including mount points and per-operation traces. That file is world-readable,
survives until /tmp cleanup, contradicts the "zero-state" claim, and is a symlink
target when the daemon runs as root (device-hosted volumes via sudo). Logging now
goes to stderr only; debug logging is opt-in at compile time.

### B-5 — `.auxinfo` handling (Medium)

When elevated, `$TMPDIR` is dropped by sudo and the aux mount point lives in
`/tmp`. `SendAuxDeviceInfo()` opened `<aux>.auxinfo` with `O_CREAT|O_TRUNC` as root
(symlink or hard link → truncate/overwrite an arbitrary file), and
`GetMountedVolumes()` trusted any file with that name (another user could make the
next dismount detach a different disk). Now: unlink + `O_EXCL|O_NOFOLLOW`, and the
file is only read if it is a regular file owned by the caller or root.

### B-6 — Password truncation (Medium)

`VolumePassword::Set(const wchar_t*)` keeps only the low byte of each character.
Characters above U+00FF lose information (e.g. "€" becomes "¬", Cyrillic/CJK lose
half their bits, decomposed accents differ from composed ones). TrueCrypt's
wxWidgets UI warned; that check disappeared with the UI. New volumes and new
passwords containing such characters are now refused with a clear message.
Existing volumes keep opening with the old encoding. A proper fix (UTF-8 with
normalisation, as VeraCrypt does) would be a format decision — see O-5.

### B-7 — PATH lookups (Medium)

`CoreService::StartElevated()` ran `execvp("sudo", …)` and wrote the admin
password to its stdin; a fake `sudo` earlier in `$PATH` (e.g. a user-writable
`/usr/local/bin` or `~/bin` for the CLI) would receive the password. DarwinFUSE
used `execlp("mount_nfs")` (standalone also `umount`). All are absolute now.

### B-8 — RNG start order (Low)

`RandomNumberGenerator::Start()` seeded the pool and then ran `Test()`, which
zeroes the pool and leaves deterministic content. Since `GetData()` always mixes
fresh `getentropy()` output before and after extraction, generated keys were not
weakened, but the documented "fix" had the opposite effect. Restored TrueCrypt's
order.

### B-9 — AES-NI missing on x86_64 (Low, performance)

`build-universal.sh` builds both slices with `NOASM=1`. That disables
`Aes_hw_cpu.asm`, and `TC_AES_HW_CPU` is then undefined on x86_64, so Intel Macs
use T-table AES. Added `Aes_hw_cpu_x86.c` (AES-NI intrinsics, runtime CPUID
check). Self-tests pass with hardware AES enabled, 2000 random sw/hw cross-checks
match, XTS throughput ≈ 7× higher on the test machine.

### B-10 … B-12, D-2 … D-4 (Low/High)

- The single-threaded NFS server busy-waited forever when a client stopped
  reading; it now waits with `poll()` and drops the client after 30 s.
- Build scripts now place their helper symlink in the private `$TMPDIR`.
- `com.apple.screenIsLocked` now also triggers "dismount on screen saver".
- Standalone DarwinFUSE joined NFS component names into FUSE paths without
  validation. `..`, `.`, names with `/` or NUL now return `NFS4ERR_BADNAME`
  before reaching the filesystem — otherwise a pass-through filesystem could be
  made to touch files outside its root.

### B-13 / D-5 — NFS daemon survives the dismount (High)

Found during testing on macOS after the audit: every mount left a process named
`Basalt` behind. DarwinFUSE accepts the kernel's connection in the mounting
process, stops the server thread, `fork()`s the daemon and restarts the event
loop there. `nfs4_server_restart()` reset `had_client`, and the loop only ends
when `had_client && num_clients == 0`. The kernel keeps using the connection
accepted before the fork and never connects again, so after the unmount the
daemon ran forever: the volume stayed open, the master keys stayed in its
memory (`fuse_service_destroy` never ran), and the decrypted image stayed
reachable through the listening socket — in 1.1.1 a loopback TCP port open to
every local process after the user had dismounted.

Fix: `had_client` survives the restart; the loop ends when no client is
connected and the mount is gone from the mount table (`getmntinfo(MNT_NOWAIT)`,
which never queries the server; for the local socket the `<socket>:/` source
must match, so a new mount on the same path is not mistaken for ours). A Linux
test reproduces the hang with the old code (server still running 5 s after the
disconnect) and passes with the fix, for the embedded and the standalone copy.

### B-14 — Volumes stay mounted when Basalt is killed (Medium)

Also found during testing: killing the app process left its volumes mounted
and accessible. The core service child now tracks the volumes it mounted and
force-dismounts them when its client disappears without an `ExitRequest`; the
app and the CLI send that message on a regular exit, so deliberately kept
volumes (dismount on quit off, CLI mounts) are unaffected.

## Open items

Items marked *Addressed* were implemented after the audit (SECURITY.md, Wave 11).

- **O-1 (Medium) CLI `--password=`** is visible in `ps` to all local users and
  ends up in shell history; the help text promotes it. Add `--password-stdin`
  (or `--password-fd`) and warn when `--password` is used.
  *Addressed:* `--password-stdin` added; `--password`/`--new-password` print a
  warning; the help text recommends the prompt or stdin.
- **O-2 (Low) Password copies.** SwiftUI `String` state, `NSData` and
  `std::wstring` temporaries in `ToWide()` are not wiped. At least clear the
  sheet's `@State` passwords after use and wipe the `wstring` buffers.
  *Addressed:* the bridge copies passwords from `NSString` straight into a wiped
  stack buffer and from there into `VolumePassword` (no `NSData`/`wstring`
  copies); the app clears password state after use. Swift `String`/`NSString`
  storage itself still cannot be wiped.
- **O-3 (Low) Sleep/logout dismount** runs in an async `Task` without a power
  assertion; the system may sleep before the dismount finishes. Use
  `IORegisterForSystemPower` and acknowledge sleep only after dismounting.
  *Addressed:* sleep is acknowledged with `IOAllowPowerChange` only after the
  dismount finished; on logout/shutdown the app delays termination until the
  volumes are dismounted.
- **O-4 (Info) Screen capture protection.** Verify on macOS 15 and 26 that
  `sharingType = .none` still hides the windows from ScreenCaptureKit-based
  recording; adjust the README claim if not.
- **O-5 (Low) Password encoding.** Consider UTF-8 (NFC) for new Basalt volumes
  with fallback to the legacy encoding on mount, instead of refusing characters.
- **O-6 (Low) Spotlight marker.** Creating `.metadata_never_index` on every mount
  writes to the outer volume (timestamps, filesystem metadata). Skip it for
  read-only and hidden-volume-protected mounts, or use `mdutil -i off`.
  *Addressed:* the marker is created only once, and never on read-only mounts or
  outer volumes mounted with hidden volume protection.
- **O-7 (Low) Elevation.** `sudo -S` fed from a custom password dialog trains users
  to type their macOS password into app dialogs. With a Developer ID, move the
  privileged operations to an `SMAppService` daemon with an XPC interface
  (system authorization prompt, code-signing requirement on the client).
- **O-8 (Info) TCP fallback.** Disable `DFUSE_TCP_FALLBACK` after verification.
  *Addressed:* verified on macOS; off by default.
- **O-9 (Info) Standalone DarwinFUSE** logs file names to stderr in foreground
  mode and `build_child_path()` silently truncates paths over 1023 bytes.
- **O-10 (Info) VeraCrypt compatibility.** SHA-256/BLAKE2s/Streebog PRFs and PIM
  are unsupported (now documented in the README).

## Verification checklist (macOS)

Run on Apple Silicon and Intel (or Rosetta), on the oldest and newest supported
macOS:

1. `bash build-universal.sh release`; "Run Self-Test…" in the app passes.
2. Mount a file container. `mount | grep basalt` shows the aux mount as
   `<…/darwinfuse.XXXXXX/nfs.sock>:/`; `lsof -nP -iTCP -sTCP:LISTEN` shows no
   Basalt/DarwinFUSE listener. Read and write a large file (> 1 GB), dismount.
3. Mount a volume created with 1.1.1 using Argon2id-Max: the badge shows
   "Argon2id-Max (legacy)", the upgrade prompt appears; after upgrading the
   volume remounts as "Argon2id-Max". Repeat with an Argon2id (standard) volume
   and a TrueCrypt 7.1a volume.
4. Create a volume with a password containing "€" → clear error; with "äöü" → works.
5. Mount and dismount a device-hosted volume (sudo path) — `/tmp` contains no
   `darwinfuse.log`; `.auxinfo` is root-owned 0600.
6. Lock the screen with Ctrl-Cmd-Q with "dismount on screen saver" enabled.
7. With "dismount when system sleeps" enabled and a volume mounted, choose
   Apple menu > Sleep: the volume is gone after wake (`pmset -g log` shows the
   sleep was delayed only briefly). Quit with Cmd-Q and from the menu bar icon:
   `mount` lists no Basalt volume afterwards. With "Force dismount" off and a file
   open on the volume, quitting asks before leaving the volume mounted.
8. Mount with "Key derivation" set to the volume's KDF and to a wrong one: the
   wrong one fails within seconds with the hint to use Auto-detect.
   `basalt-cli --password-stdin --kdf=argon2id-max …` with the password piped in.
9. Switch the system language (e.g. German, Japanese): menus, sheets, errors and
   the upgrade prompt are translated, no text is clipped (Settings window, wizard).
10. After dismounting all volumes and quitting, `ps -ax | grep -i [b]asalt` lists
    no process (B-13).
11. Mount a volume, `kill -9` the app's main process: within a few seconds the
    volume is dismounted and no Basalt process is left (B-14). With "dismount on
    quit" off, a regular quit keeps the volume mounted.
